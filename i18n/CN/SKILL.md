# 全网招聘寻访与能力匹配工作流

## 用途

把业务方的岗位/用工要求转化为可执行的人才寻访行动：结构化需求 → 设计并执行全网检索 → 建立能力模型并精准匹配 → 输出寻访报告与行动建议。

## 使用时机

- 用户给出 JD 或业务要求，要求「找人 / 检索人才 / 看人才市场 / 对标竞对招聘」
- 用户要求按能力维度筛选、匹配、排序候选线索
- 用户要求输出人才寻访报告、人才地图或招聘市场洞察简报

## 五步流程

### 第 1 步：需求澄清与结构化

把业务要求转成结构化人才画像；缺失信息先提问，不假设。输出四张表：

- **硬性条件**：职级 / 年限 / 学历 / 行业背景 / 地点 / 薪资带宽 / 到岗时间
- **能力维度**：专业硬技能、业务软技能、文化适配项
- **权重标注**：必备项（一票否决）/ 加分项 / 参考项
- **检索对象**：目标公司、目标人群、替代人群

### 第 2 步：检索策略设计

基于人才画像生成检索关键词矩阵（岗位词 × 技能词 × 场景词 × 渠道词）与目标渠道清单。方法与示例见 `references/search-playbook.md`：

- 渠道分层：招聘站点 / 社交与专业社区 / 竞对动态 / 行业报告
- 每轮检索设定明确目标：验证供给密度 / 挖具体线索 / 查薪资与市场行情
- 关键词变体：同义词、缩写、中英文混排（如「后端」「服务端」「Backend」）

### 第 3 步：全网检索执行

逐轮执行检索，遵守以下纪律：

- 每轮记录：检索式、渠道、命中数量、信源质量、获取时间
- 交叉验证：同一结论至少两个独立信源；优先官方/一手来源
- 行情与招聘动态类数据必须标注获取日期
- 单轮无有效命中时，回到第 2 步放宽关键词或更换渠道，不死磕同一检索式

### 第 4 步：能力建模与精准匹配

1. 把岗位要求拆成 5-8 个可评分能力维度，建立 0-5 级行为锚定（评什么、几分长什么样）
2. 对每条候选线索按维度打分，只基于简历/主页/项目描述中的证据打分，无证据不评分
3. 运行 `scripts/match_score.py` 计算加权匹配度（输入评分 JSON，输出总分、优势项、缺口项、一票否决标记）
4. 评分模型、锚定示例与匹配度分级见 `references/capability-matching-model.md`

### 第 5 步：寻访报告输出

按 `references/report-template.md` 输出报告：结论先行、人才供给概况、Top 线索表（含匹配度与证据）、触达建议、风险与备选。结尾给业务方 3 个可立即执行的下一步动作。

## 铁律

- 只依据岗位相关能力与证据评价，严禁年龄、性别、地域、婚育、户籍等歧视性维度
- 不编造信源与候选人；检索不到就如实说明，并给出扩搜建议
- 只使用公开渠道信息，保护个人隐私
- 所有结论标注信源与获取时间
