# 现实岗位设计研究手册（Search Playbook）

> 配合 `recruit-web-sourcing` 技能第 2 步使用。目标：用有限的检索轮次，系统性搞清现实中某个岗位是怎么设计的——职责、任职要求、工作流、协作界面、考核指标、工具栈。

## 一、渠道分层矩阵

| 层级 | 渠道类型 | 典型渠道 | 主要用途 | 信源质量 |
|------|---------|---------|---------|---------|
| L1 | 招聘站点 | Boss直聘、智联招聘、猎聘、拉勾、前程无忧；海外：LinkedIn、Indeed、Glassdoor | 岗位职责、任职要求、薪资带宽、在招密度 | 高（一手 JD） |
| L2 | 组织设计资料 | 岗位说明书、职级体系、R&R（职责表）、组织架构图、公司公开手册/Wiki | 岗位定位、汇报关系、职责边界 | 高（一手资料，但公开的少） |
| L3 | 从业者社区 | 脉脉、知乎、V2EX、GitHub、Stack Overflow、掘金、公众号、技术博客 | 真实工作流、协作方式、日常痛点、工具栈 | 中高（本人发布，需甄别个案） |
| L4 | 行业报告与方法论 | 咨询公司岗位模型、HR 方法论、敏捷/DevOps/ITIL 等实践框架、薪酬调研报告 | 岗位设计范式、考核指标、市场行情 | 中（注意发布时间与适用边界） |

**执行顺序**：先 L1 摸岗位职责与任职要求 → 再 L2/L3 补工作流、协作与工具栈 → 最后用 L4 校准设计范式与考核指标。

## 二、关键词矩阵构建法

按四个词族交叉组合，每轮检索取 2-4 个组合：

| 词族 | 说明 | 示例（数据分析师） |
|------|------|-------------------|
| 岗位词 | 职位名称的同义与变体 | 数据分析师、数据运营、BI 工程师、Data Analyst |
| 职责词 | 岗位干什么 | 用户行为分析、报表体系、AB 实验、指标体系搭建 |
| 场景词 | 业务场景与行业 | 电商、SaaS、金融科技、广告投放 |
| 设计词 | 岗位设计相关资料 | 岗位说明书、职责、任职要求、绩效考核、OKR、职级 |

**组合示例**：
- 「数据分析师 岗位职责 任职要求 招聘」→ 摸 L1 职责与要求
- 「数据分析师 一天的工作 工作流」→ 挖 L3 真实日常
- 「数据分析师 绩效考核 指标 OKR」→ 查考核指标
- 「site:zhihu.com 数据分析师 工作日常」→ 定向挖从业者分享

## 三、检索指令速查

| 指令 | 作用 | 示例 |
|------|------|------|
| `site:` | 限定站点 | `site:linkedin.com data analyst` |
| `intitle:` | 标题必含 | `intitle:岗位说明书 产品经理` |
| `filetype:` | 限定文件类型 | `filetype:pdf 岗位说明书 财务` |
| `""` | 精确匹配 | `"用户增长负责人"` |
| `-` | 排除噪音 | `数据分析 -培训 -保安` |
| 时间过滤 | 控制时效 | JD/方法论类检索优先选近 3 年 |

## 四、岗位设计六要素采集清单

每研究一个岗位，按这张表过一遍，缺项继续补检：

| 要素 | 采集内容 | 主渠道 |
|------|---------|--------|
| 职责 | 具体干什么，拆到可执行动作项 | L1 JD、L2 岗位说明书 |
| 任职要求 | 知识、技能、经验、资质证书 | L1 JD |
| 工作流 | 工作步骤、顺序、周期、检查点 | L3 从业者分享、L4 方法论 |
| 协作界面 | 上游给什么、下游接什么、向谁汇报 | L2 组织架构、L3 |
| 考核指标 | 怎么算干得好（质量/效率/结果） | L4 方法论、L1 JD 加分描述 |
| 工具栈 | 用什么工具、系统、模板干活 | L3、L1 JD |

## 五、常见岗位研究路径（速查）

| 岗位类型 | 优先渠道 | 研究技巧 |
|---------|---------|---------|
| 研发（前后端/算法） | L1 + GitHub/掘金/技术博客 | 看 JD 技能要求 + 工程师写的真实工作流与协作吐槽 |
| 产品 | L1 + 脉脉/知乎/公众号 | 搜产品经理写的 PRD 流程、需求评审经验 |
| 设计 | L1 + Behance/Dribbble/站酷 | 看作品集说明 + 设计师写的协作流程 |
| 运营/市场 | L1 + 公众号/知乎 | 搜操盘过的知名案例复盘（署名+流程） |
| 销售/商务 | L1 + 脉脉/行业媒体 | 按目标客户群反查「做过同类客户」的岗位设计 |
| 职能（HR/财务/法务） | L1 + 垂直社区 + L4 | 按行业资质证书反查（CPA、法律职业资格等） |
| 管理岗 | L2 + L4 + L3 | 重点查汇报关系、协作界面与考核指标 |

## 六、检索纪律

- 每轮检索只验证一个假设，避免一锅炖
- 同一结论至少两个独立信源交叉验证；职责与任职要求以 L1 在招 JD 为主、报告为辅
- 所有研究结论必须标注「数据获取时间：YYYY-MM-DD」
- 连续两轮无有效命中 → 换词族或换渠道，不重复同一检索式超过两次
- 从业者社区内容注意甄别个案与共识：多人独立描述一致才可作为岗位设计证据
