# 能力建模与精准匹配模型

> 配合 `recruit-web-sourcing` 技能第 4 步使用。目标：把「合不合适」从主观判断变成可复现的评分。

## 一、能力维度拆解法

从 JD 和业务要求中提取 5-8 个能力维度，按三类归口：

| 类别 | 含义 | 示例 |
|------|------|------|
| 专业硬技能 | 干活的硬功夫 | 分布式架构设计、SQL 优化、投放策略制定 |
| 业务软技能 | 成事的软实力 | 跨部门推进、客户谈判、团队带教 |
| 文化适配 | 与组织匹配的底色 | 创业节奏适应、数据驱动决策、开放协作 |

**拆解规则**：
- 每个维度必须可观察、可提问、可验证，拒绝「有潜力」「感觉不错」这类虚词
- 同一维度不重复归两类；JD 里没提但业务方口头强调的，补录并标注来源
- 维度数量控制在 5-8 个：少于 5 个容易漏评，多于 8 个权重稀释

## 二、0-5 级行为锚定量表

每个维度按五级定义「长什么样」，评分时对号入座：

| 分数 | 等级 | 行为锚定（通用表述） |
|------|------|---------------------|
| 5 | 精通 | 有可验证的标杆产出（主导过同规模/同难度项目，成果被行业或公司认可） |
| 4 | 熟练 | 独立完整交付过同类工作，质量稳定，几乎不需要指导 |
| 3 | 胜任 | 在指导下完成过同类工作，能处理常规场景 |
| 2 | 入门 | 接触过但未独立交付，或仅有培训/课程级经验 |
| 1 | 了解 | 仅概念认知，无实践 |
| 0 | 无证据 | 公开信息中找不到任何证据（不表示不会，表示无法验证） |

**锚定示例（以「高并发系统设计」为例）**：
- 5：主导过日均千万级请求系统的架构设计，有公开分享或可查案例
- 4：独立负责过百万级请求系统的核心模块
- 3：参与过高并发系统开发，负责其中若干模块
- 2：学习/练习项目涉及，未上生产
- 1：仅课程或概念了解
- 0：无任何相关信息

**证据规则**：无证据 = 0 分并标注「待验证」；面试/背调后获得的证据可更新评分，更新时保留评分历史。

## 三、权重设置

| 权重级 | 含义 | 建议权重 | 计分规则 |
|--------|------|---------|---------|
| 必备项（一票否决） | 不满足则整体不匹配 | 0.25-0.35 | 得分 ≤2 → 标记 VETO，总分仍计算但结论必须提示 |
| 加分项 | 显著超出则优先 | 0.10-0.20 | 正常计入 |
| 参考项 | 影响边缘判断 | 0.05-0.10 | 正常计入 |

权重之和必须为 1.0；必备项一般设 1-2 个，超过 2 个说明画像没收敛。

## 四、匹配度计算与分级

用 `scripts/match_score.py` 计算：加权平均（0-5 分制）× 20 = 匹配度百分制。

| 匹配度 | 分级 | 行动建议 |
|--------|------|---------|
| ≥85 | A 优先寻访 | 立即触达，准备定向话术 |
| 70-84 | B 可培养 | 触达同时评估缺口项的培养成本与周期 |
| 50-69 | C 谨慎 | 仅当供给紧张时作为替代人选，明确缺口 |
| <50 | D 不匹配 | 不进入寻访清单 |
| 任意必备项 ≤2 | 一票否决 | 无论总分，默认 D，除非业务方明确豁免 |

## 五、match_score.py 用法

```bash
# 输入 JSON（文件或标准输入），输出匹配度报告
python scripts/match_score.py scores.json
echo '{"dimensions":[{"name":"高并发系统设计","weight":0.3,"level":"must","score":4,"evidence":"主导过日均千万级请求系统"},{"name":"团队带教","weight":0.2,"level":"plus","score":3,"evidence":"带过5人小组"}]}' | python scripts/match_score.py
```

输入格式：

```json
{
  "dimensions": [
    {
      "name": "高并发系统设计",
      "weight": 0.3,
      "level": "must | plus | ref",
      "score": 4,
      "evidence": "主导过日均千万级请求系统架构"
    }
  ]
}
```

输出：匹配度总分、分级、各维度明细、优势项（≥4 分）、缺口项（<3 分）、一票否决标记。

## 六、使用纪律

- 评分只基于公开渠道证据，不脑补；证据字段必填
- 同一岗位的所有候选线索用同一套维度和权重，保证可比
- 业务要求变化时，先改画像和权重，再重评，不搞「看人下菜碟」
- 输出匹配度时必须同时给出置信度说明（证据充分/部分待验证）
