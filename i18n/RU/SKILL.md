# Рабочий процесс веб-поиска кандидатов и сопоставления компетенций

## Назначение

Превратить требования бизнеса к роли или штату в исполнимый план подбора: структурировать требования, спроектировать и выполнить поиск по всему интернету, построить модель компетенций и точно сопоставить, затем выдать отчёт по подбору с дальнейшими действиями.

## Когда использовать

- Пользователь даёт JD или требования бизнеса и просит найти людей, поискать таланты, просканировать рынок или сравнить найм конкурентов
- Пользователь просит отфильтровать, сопоставить или ранжировать лиды-кандидаты по измерениям компетенций
- Пользователь просит отчёт по подбору, карту талантов или брифинг по рынку найма

## Рабочий процесс из пяти шагов

### Шаг 1: Уточнение и структурирование требований

Преобразовать требования бизнеса в структурированный профиль таланта; при нехватке данных — задавать вопросы, никогда не додумывать. Вывести четыре таблицы:

- **Жёсткие условия**: грейд / стаж / образование / отрасль / локация / зарплатная вилка / дата выхода
- **Измерения компетенций**: hard skills, soft skills, элементы культурного fit
- **Веса**: обязательные (жёсткое вето) / desirable / справочные
- **Цели поиска**: целевые компании, целевые группы, альтернативные группы

### Шаг 2: Проектирование стратегии поиска

По профилю таланта построить матрицу ключевых слов (роль x навык x сценарий x канал) и список целевых каналов. Метод и примеры — в `references/search-playbook.md`:

- Слои каналов: job-сайты / социальные и профессиональные сообщества / действия конкурентов / отраслевые отчёты
- Чёткая цель на каждый раунд: проверить плотность предложения / добыть конкретные лиды / сверить зарплатные ориентиры
- Варианты ключевых слов: синонимы, аббревиатуры, смешение EN-ZH (например, «бэкенд», «серверная часть», «Backend»)

### Шаг 3: Выполнение поиска по всему интернету

Выполнять раунд за раундом с соблюдением дисциплины:

- Фиксировать каждый раунд: запрос, канал, число попаданий, качество источника, дата получения
- Перекрёстная проверка: минимум два независимых источника на вывод; приоритет официальным и первичным
- Все рыночные данные и данные о найме — с датой получения
- Если раунд не дал полезного, вернуться к шагу 2: расширить ключевые слова или сменить канал; один и тот же запрос не повторять больше двух раз

### Шаг 4: Модель компетенций и точное сопоставление

1. Разбить требования к роли на 5-8 оцениваемых измерений и построить шкалу поведенческих анкеров 0-5 (что оценивается и как выглядит каждый уровень)
2. Оценить каждый лид-кандидат по каждому измерению только на основе доказательств из резюме, профилей или описаний проектов; нет доказательств — нет оценки
3. Запустить `scripts/match_score.py` для взвешенной оценки (вход: JSON с оценками; выход: total, сильные стороны, пробелы, флаги вето)
4. Модель оценивания, примеры анкеров и пороги grade — в `references/capability-matching-model.md`

### Шаг 5: Формирование отчёта по подбору

Следовать `references/report-template.md`: отчёт «сначала выводы» — обзор предложения талантов, таблица топ-лидов (оценка + доказательства), рекомендации по контакту, риски и запасные планы. Завершить тремя немедленно исполняемыми действиями для бизнеса.

## Железные правила

- Оценивать только релевантные должности компетенции и доказательства; никогда — возраст, пол, регион, семейное положение, прописку или иные дискриминационные измерения
- Не выдумывать источники и кандидатов; если поиск пуст, честно сказать об этом и предложить, как его расширить
- Только открытые каналы; защищать приватность кандидатов
- К каждому выводу прикладывать источник и дату получения
