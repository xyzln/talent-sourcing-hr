# Плейбук стратегии поиска

> Используется с шагами 2 и 3 навыка `recruit-web-sourcing`. Цель: системно покрыть информацию о предложении талантов за ограниченное число раундов поиска.

## 1. Матрица слоёв каналов

| Слой | Тип канала | Типичные каналы | Основное применение | Качество источника |
|------|-----------|-----------------|---------------------|--------------------|
| L1 | Job-сайты | Boss Zhipin, Zhaopin, Liepin, Lagou, 51job; зарубежные: LinkedIn, Indeed, Glassdoor | Открытые вакансии, зарплатные вилки, требования, плотность талантов | Высокое (первичные JD) |
| L2 | Социальные и профессиональные сообщества | Maimai, Zhihu, GitHub, Stack Overflow, V2EX, Juejin, Behance/Dribbble (дизайн) | Лиды-кандидаты, реальные работы, техническое влияние | Средне-высокое (публикации авторов) |
| L3 | Действия конкурентов и индустрия | Career-страницы конкурентов, новости о финансировании/продуктах, отраслевые медиа | Направление расширения конкурентов, сигналы потоков талантов | Среднее (нужна перекрёстная проверка) |
| L4 | Отраслевые отчёты и данные | Обследования компенсаций, отчёты о рынке талантов, белые книги платформ | Зарплатные ориентиры, тренды спроса и предложения | Среднее (проверяйте дату публикации) |

**Порядок исполнения**: сначала L1 для плотности предложения и зарплатных вилок, затем L2/L3 для добычи конкретных лидов, и наконец L4 для калибровки рыночных выводов.

## 2. Построение матрицы ключевых слов

Перекрёстно комбинируйте четыре семейства слов, используя 2-4 комбинации за раунд:

| Семейство | Описание | Пример (Senior Backend Engineer) |
|-----------|----------|----------------------------------|
| Слова роли | Синонимы и варианты названия | Backend Engineer, Server-side Engineer, Java Developer, Backend Engineer |
| Слова навыков | Hard skills и стек | распределённые системы, микросервисы, высокая нагрузка, Kubernetes, Go, Spring Cloud |
| Слова сценария | Бизнес-сценарии и индустрия | e-commerce-платформа, платёжные системы, SaaS, fintech, рекламные системы |
| Слова канала | Сайты и внутрисайтовый таргетинг | site:zhipin.com, site:linkedin.com, site:github.com |

**Примеры комбинаций**:
- "senior backend engineer microservices high concurrency hiring" -> предложение L1
- "site:github.com high-concurrency Java open source" -> технические лиды L2
- "payment system architect hiring salary" -> зарплатная вилка

## 3. Шпаргалка по операторам поиска

| Оператор | Назначение | Пример |
|----------|-----------|--------|
| `site:` | Ограничить сайт | `site:liepin.com algorithm engineer` |
| `intitle:` | Термин в заголовке | `intitle:hiring data analyst` |
| `filetype:` | Ограничить тип файла | `filetype:pdf compensation report 2025` |
| `""` | Точное совпадение | `"head of user growth"` |
| `-` | Исключить шум | `hiring -training -security` |
| Фильтр времени | Контроль свежести | Для новостей и вакансий — последние 3-12 месяцев |

## 4. Оценка плотности предложения (как на шаге 3 судить о «найти ли таланты?»)

Отслеживайте четыре метрики за раунд и фиксируйте их в отчёте по подбору:

1. **Объём открытых вакансий**: порядок величины на каналах L1 (например, «~500+ на Boss Zhipin»)
2. **Зарплатная вилка**: доминирующий диапазон и процентили (P25/P50/P75), с датой
3. **Скопления талантов**: в каких компаниях/городах/сообществах концентрируется аудитория (список конкурентов)
4. **Сигналы дефицита**: долгоживущие вакансии, растущие зарплаты, снижение требований (недостаток предложения) или наоборот

**Уровни выводов**:
- Достаточное предложение (большой объём вакансий, стабильные зарплаты) -> умеренно повысить планку; фокус отбора на соответствии компетенций
- Дефицит предложения (мало вакансий, растущие зарплаты, снижение требований) -> начинать заранее, расширять альтернативные группы, повышать бюджет на компенсации
- Структурный дефицит (большой пул, но мало подходящих по жёстким условиям) -> ужесточить приоритет блокирующих критериев, искать «ближайшее окружение»

## 5. Типовые пути подбора по ролям (шпаргалка)

| Тип роли | Приоритетные каналы | Тактика добычи лидов |
|----------|---------------------|----------------------|
| Инженерия (фронт/бэк/алгоритмы) | L1 + GitHub/Juejin | Искать контрибьюторов опенсорса и авторов техблогов |
| Продукт | L1 + Maimai/Zhihu | Искать авторов продуктовых анализов и новости конкурентов |
| Дизайн | L1 + Behance/Dribbble | Смотреть портфолио напрямую; искать авторов по типу проекта |
| Операции/маркетинг | L1 + WeChat-каналы/Zhihu | Искать по подписям известных кейсов |
| Продажи/BD | L1 + Maimai | Обратный поиск по сегменту клиентов: «кто работал с такими клиентами» |
| Корпоративные функции (HR/финансы/право) | L1 + вертикальные сообщества | Обратный поиск по сертификатам (CPA, адвокатский экзамен и т.д.) |

## 6. Дисциплина поиска

- Каждый раунд проверяет ровно одну гипотезу; никаких «всё в одном» запросов
- Перекрёстная проверка каждого вывода минимум двумя независимыми источниками; по зарплатам приоритет первичных JD над отчётами
- Все рыночные данные с меткой «дата получения: YYYY-MM-DD»
- Два пустых раунда подряд -> менять семейство слов или канал; один и тот же запрос не повторять больше двух раз
