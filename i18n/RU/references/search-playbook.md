# Пособие по исследованию дизайна реальных должностей

> Используется на шаге 2 навыка `recruit-web-sourcing`. Цель: за ограниченное число раундов поиска системно понять, как устроена реальная должность — обязанности, требования, процесс, интерфейсы взаимодействия, метрики, инструментарий.

## 1. Матрица слоёв каналов

| Слой | Тип канала | Типичные каналы | Основное применение | Качество источника |
|------|-----------|-----------------|---------------------|--------------------|
| L1 | Job-сайты | Boss Zhipin, Zhaopin, Liepin, Lagou, 51job; зарубеж: LinkedIn, Indeed, Glassdoor | Обязанности, требования, зарплатные вилки, плотность найма | Высокое (первичные JD) |
| L2 | Материалы оргдизайна | Должностные инструкции, системы грейдов, таблицы R&R, оргсхемы, публичные корпоративные handbook'ы | Позиционирование роли, подчинение, границы ответственности | Высокое (первичка, но редко публична) |
| L3 | Сообщества практиков | Maimai, Zhihu, V2EX, GitHub, Stack Overflow, Juejin, WeChat-каналы, tech-блоги | Реальные процессы, стили взаимодействия, повседневные боли, инструментарий | Средне-высокое (самопубликации; осторожно с единичными случаями) |
| L4 | Отраслевые отчёты и методологии | Консалтинговые модели ролей, HR-методологии, практики Agile/DevOps/ITIL, зарплатные исследования | Парадигмы дизайна, метрики, рыночные ориентиры | Среднее (внимание к дате публикации и применимости) |

**Порядок исполнения**: сначала L1 — обязанности и требования; затем L2/L3 — процесс, взаимодействие и инструментарий; наконец L4 — калибровка парадигм дизайна и метрик.

## 2. Построение матрицы ключевых слов

Пересечение четырёх семейств слов, 2-4 комбинации за раунд:

| Семейство | Описание | Пример (аналитик данных) |
|-----------|----------|--------------------------|
| Слова роли | Синонимы и варианты названия | аналитик данных, data-операции, BI-инженер, Data Analyst |
| Слова обязанностей | Что роль делает | анализ поведения пользователей, система отчётности, A/B-тесты, фреймворк метрик |
| Слова сценария | Бизнес-сценарии и отрасли | e-commerce, SaaS, финтех, рекламные системы |
| Слова дизайна | Материалы о дизайне должности | должностная инструкция, обязанности, требования, оценка эффективности, OKR, грейды |

**Примеры комбинаций**:
- «аналитик данных обязанности требования вакансия» → разведка L1 по обязанностям и требованиям
- «аналитик данных обычный рабочий день процесс» → добыча L3 о реальной рутине
- «аналитик данных KPI оценка эффективности OKR» → проверка метрик
- «site:zhihu.com data analyst день из жизни» → точечный сбор рассказов практиков (на китайскоязычных сайтах — запрос на китайском)

## 3. Шпаргалка по операторам поиска

| Оператор | Эффект | Пример |
|----------|--------|--------|
| `site:` | Ограничение сайта | `site:linkedin.com data analyst` |
| `intitle:` | Заголовок содержит | `intitle:должностная инструкция продакт-менеджер` |
| `filetype:` | Тип файла | `filetype:pdf должностная инструкция финансы` |
| `""` | Точное совпадение | `"руководитель роста пользователей"` |
| `-` | Исключение шума | `аналитик данных -курсы -охрана` |
| Фильтр времени | Контроль свежести | Поиск JD и методологий — преимущественно за последние 3 года |

## 4. Чек-лист сбора шести элементов дизайна должности

По каждой изученной должности пройти эту таблицу; пробелы — догоняющие поиски:

| Элемент | Что собирать | Основные каналы |
|---------|--------------|-----------------|
| Обязанности | Что реально делает, до исполнимых действий | L1 JD, L2 должностные инструкции |
| Требования | Знания, навыки, опыт, квалификация | L1 JD |
| Процесс | Шаги работы, порядок, цикличность, контрольные точки | L3 рассказы практиков, L4 методологии |
| Взаимодействие | Что поступает на вход, что на выход, кому подчиняется | L2 оргсхемы, L3 |
| Метрики | Что значит «сделано хорошо» (качество/эффективность/результат) | L4 методологии, L1 пожелания в JD |
| Инструментарий | Инструменты, системы, шаблоны | L3, L1 JD |

## 5. Пути исследования по типам ролей (шпаргалка)

| Тип роли | Приоритетные каналы | Приёмы исследования |
|----------|--------------------|---------------------|
| Разработка (фронт/бэк/алго) | L1 + GitHub/Juejin/tech-блоги | Требования навыков из JD + рассказы инженеров о процессе и взаимодействии |
| Продукт | L1 + Maimai/Zhihu/WeChat-каналы | Поиск разборов PRD-процесса и ревью требований от продактов |
| Дизайн | L1 + Behance/Dribbble/Zcool | Описания в портфолио + рассказы дизайнеров о совместной работе |
| Операции/маркетинг | L1 + WeChat-каналы/Zhihu | Именные разборы известных кейсов (автор + процесс) |
| Продажи/BD | L1 + Maimai/отраслевые медиа | Реверс-лук дизайна роли по целевым сегментам клиентов («работал с такими клиентами») |
| Функциональные (HR/финансы/юристы) | L1 + вертикальные сообщества + L4 | Реверс-лук по отраслевым сертификатам (CPA, адвокатская квалификация и т.п.) |
| Управление | L2 + L4 + L3 | Акцент на подчинении, интерфейсах взаимодействия и метриках |

## 6. Дисциплина поиска

- Каждый раунд проверяет одну гипотезу; никаких запросов «всё в одном»
- Перекрёстная проверка каждого вывода минимум двумя независимыми источниками; обязанности и требования — преимущественно из L1 (живые JD), отчёты как дополнение
- Все выводы исследования — с отметкой «дата получения данных: YYYY-MM-DD»
- Два пустых раунда подряд → смените семейство слов или канал; один и тот же запрос не повторять больше двух раз
- В контентном сообществе различайте единичные случаи и консенсус: закономерность считать доказательством дизайна должности, только если её независимо описали несколько человек
