# Модель компетенций и точное сопоставление

> Используется с шагом 4 навыка `recruit-web-sourcing`. Цель: превратить «подходит ли?» из интуиции в воспроизводимую оценку.

## 1. Декомпозиция измерений компетенций

Извлеките 5-8 измерений компетенций из JD и требований бизнеса, сгруппировав по трём категориям:

| Категория | Смысл | Примеры |
|-----------|-------|---------|
| Hard skills | Ремесло выполнения работы | проектирование распределённых архитектур, оптимизация SQL, стратегия кампаний |
| Soft skills бизнеса | Ремесло доведения дел | кросс-функциональное продвижение, переговоры с клиентами, наставничество |
| Культурный fit | База соответствия организации | адаптация к стартап-ритму, решения на данных, открытое сотрудничество |

**Правила декомпозиции**:
- Каждое измерение должно быть наблюдаемым, спрашиваемым и проверяемым; отсекайте размытые слова вроде «есть потенциал» или «выглядит подходяще»
- Измерение принадлежит только одной категории; если бизнес акцентировал устно, но этого нет в JD, зафиксируйте и укажите источник
- Держите 5-8 измерений: меньше 5 — рискуете упустить, больше 8 — размываются веса

## 2. Шкала поведенческих анкеров 0-5

Определите каждое измерение пятью уровнями «как это выглядит»; оценка — по соответствию доказательств анкеру:

| Балл | Уровень | Поведенческий анкер (общая формулировка) |
|------|---------|------------------------------------------|
| 5 | Эксперт | Проверяемый эталонный результат (руководил проектами того же масштаба/сложности; результат признан индустрией или компанией) |
| 4 | Уверенно | Самостоятельно доводил похожую работу до конца; стабильное качество; почти без подсказок |
| 3 | Компетентен | Выполнял похожую работу под руководством; справляется с типовыми сценариями |
| 2 | Начальный | Знакомство без самостоятельного выполнения или только учебный опыт |
| 1 | Осведомлён | Только концептуальные знания; без практики |
| 0 | Нет доказательств | В открытой информации нет доказательств (не «не умеет», а «нельзя проверить») |

**Пример анкера («проектирование высоконагруженных систем»)**:
- 5: Руководил архитектурой системы на 10М+ запросов в сутки; публичный доклад или проверяемый кейс
- 4: Самостоятельно вёл ключевые модули системы на миллион запросов
- 3: Участвовал в разработке высоконагруженной системы, отвечая за несколько модулей
- 2: Только учебные/пет-проекты; не в продакшене
- 1: Уровень курса или концепции
- 0: Нет релевантной информации

**Правило доказательств**: нет доказательств = 0 с пометкой «требует проверки»; доказательства, полученные позже на интервью/проверке, могут обновить оценку — историю оценок сохраняйте.

## 3. Веса

| Уровень веса | Смысл | Рекомендуемый вес | Правило подсчёта |
|--------------|-------|-------------------|------------------|
| Обязательный (жёсткое вето) | Не выполнено — общий нематч | 0.25-0.35 | Оценка <=2 -> флаг VETO; total считается, но вывод обязан это отметить |
| Желательный | Значительное превышение — приоритет | 0.10-0.20 | Учитывается обычно |
| Справочный | Влияет на пограничные решения | 0.05-0.10 | Учитывается обычно |

Сумма весов должна быть 1.0; обязательных ставьте 1-2 — больше 2 означает, что профиль не сошёлся.

## 4. Расчёт оценки и grade

Через `scripts/match_score.py`: взвешенное среднее (0-5) x 20 = оценка соответствия (0-100).

| Оценка | Grade | Рекомендуемое действие |
|--------|-------|------------------------|
| >=85 | A Приоритетный контакт | Связаться немедленно с точечным сообщением |
| 70-84 | B Развиваемый | Контакт + оценка стоимости и сроков закрытия пробелов |
| 50-69 | C Осторожно | Запасной вариант только при дефиците; пробелы указать явно |
| <50 | D Не подходит | Не включать в список подбора |
| Любой обязательный <=2 | Жёсткое вето | По умолчанию D независимо от total, если бизнес явно не сделал исключение |

## 5. Использование match_score.py

```bash
# Входной JSON (файл или stdin), на выходе отчёт о соответствии
python scripts/match_score.py scores.json
echo '{"dimensions":[{"name":"Проектирование высоконагруженных систем","weight":0.3,"level":"must","score":4,"evidence":"Руководил архитектурой системы на 10М+ запросов/сутки"},{"name":"Наставничество","weight":0.2,"level":"plus","score":3,"evidence":"Вёл группу из 5 человек"}]}' | python scripts/match_score.py
```

Формат входа:

```json
{
  "dimensions": [
    {
      "name": "Проектирование высоконагруженных систем",
      "weight": 0.3,
      "level": "must | plus | ref",
      "score": 4,
      "evidence": "Руководил архитектурой системы на 10М+ запросов в сутки"
    }
  ]
}
```

Вывод: общая оценка соответствия, grade, разбивка по измерениям, сильные стороны (>=4), пробелы (<3) и флаги жёсткого вето.

## 6. Дисциплина использования

- Оценка только на доказательствах из открытых каналов; без домыслов; поле evidence обязательно
- Все лиды по одной роли оцениваются по одним измерениям и весам — для сравнимости
- При изменении требований бизнеса сначала меняйте профиль и веса, потом переоценивайте — без «подгонки под человека»
- Всегда указывайте оценку вместе с пометкой достоверности (доказательств достаточно / частично ожидают проверки)
