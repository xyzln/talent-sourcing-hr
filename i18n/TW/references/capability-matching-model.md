# 崗位 → 智能體設計映射模型

> 配合 `recruit-web-sourcing` 技能第 3、4 步使用。目標：把「崗位設計」翻譯成「agent 設計」，並用可復現的覆蓋度評分驗證設計完整性。

## 一、崗位設計要素 → Agent 設計要素映射表

| 崗位設計要素 | Agent 設計要素 | 落地位置 |
|-------------|---------------|---------|
| 角色定位（這崗位是干什么的） | 智能體定位 | frontmatter description + 人格開場段 |
| 職責（具體干什么） | 技能清單與工作流步驟 | skills 陣列 + 工作流章節 |
| 任職要求（靠什么勝任） | 能力錨定與邊界鐵律 | 人格核心能力 + 鐵律/注意事項 |
| 工作流（怎么干、什么順序） | 工作流步驟與檢查點 | 工作流章節（每步有動作和產出） |
| 協作介面（跟誰打交道） | 輸入輸出規格與交接協議 | 輸出規範 + 觸發/退出條件 |
| 考核指標（怎么算干得好） | 驗收標準與品質門檻 | 輸出規範中的合格線 |
| 工具棧（用什么干） | 工具與腳本清單 | scripts/ + 參考手冊 + 工具說明 |

**映射規則**：
- 崗位上有的要素，agent 必須有對應設計；崗位上沒有的，agent 也不許憑空發明
- 每項映射必須能回溯到崗位研究證據（信源 + 取得時間）
- 一個崗位要素可以映射到多個 agent 要素，但一個 agent 要素必須至少有一個崗位來源

## 二、Agent 設計覆蓋度錨定（0-5 級）

對每個 agent 設計維度打分，對照崗位研究證據「對號入座」：

| 分數 | 等級 | 行為錨定（通用表述） |
|------|------|---------------------|
| 5 | 完整覆蓋 | 崗位要素全部翻譯，且每項都有證據支撐，可直接落地 |
| 4 | 覆蓋無遺漏 | 主要要素全部覆蓋，細節處可再打磨 |
| 3 | 基本覆蓋 | 主體覆蓋，但有明確小缺口（缺驗收標準/缺觸發條件等） |
| 2 | 部分覆蓋 | 只覆蓋了一半左右要素，多處憑感覺補 |
| 1 | 名義覆蓋 | 提到了該維度，但沒有可執行內容 |
| 0 | 無證據 | 崗位研究中找不到支撐該設計的任何證據（不表示不該做，表示無法驗證） |

**證據規則**：無證據 = 0 分並標註「待驗證」；補充檢索獲得證據後可更新評分，更新時保留評分歷史。

## 三、常見設計維度與權重

從崗位設計研究中提取 5-8 個設計維度，按三類歸口：

| 權重級 | 含義 | 建議權重 | 計分規則 |
|--------|------|---------|---------|
| 核心項（一票否決） | 缺了 agent 就不成立 | 0.25-0.35 | 得分 ≤2 → 標記 VETO，總分仍計算但結論必須提示 |
| 加分項 | 顯著提升 agent 品質 | 0.10-0.20 | 正常計入 |
| 參考項 | 影響邊緣判斷 | 0.05-0.10 | 正常計入 |

**典型維度**（按崗位裁剪，不必全用）：
- 核心：人格定位清晰、職責覆蓋、工作流完整
- 加分：協作介面明確、驗收標準可執行、工具完備
- 參考：輸出格式規範、時效標註機制

權重之和必須為 1.0；核心項一般設 1-2 個，超過 2 個說明設計沒收斂。

## 四、設計覆蓋度計算與分級

用 `scripts/match_score.py` 計算：加權平均（0-5 分制）× 20 = 覆蓋度百分制。

| 覆蓋度 | 分級 | 行動建議 |
|--------|------|---------|
| ≥85 | A 可直接落地 | 按規格直接建成專家包 / 技能 / 子 agent |
| 70-84 | B 基本可用 | 落地同時補齊缺口項（補研究或補設計） |
| 50-69 | C 有缺口 | 先補崗位研究或補設計，再落地 |
| <50 | D 不匹配 | 回到第 2 步重新研究崗位，不急著生成 |
| 任意核心項 ≤2 | 一票否決 | 無論總分，預設 D，除非需求方明確豁免 |

## 五、match_score.py 用法

```bash
# 輸入 JSON（檔案或標準輸入），輸出覆蓋度報告
python scripts/match_score.py scores.json
echo '{"dimensions":[{"name":"人格定位清晰","weight":0.3,"level":"must","score":4,"evidence":"崗位角色定義明確：負責用戶行為分析並輸出可執行結論"},{"name":"職責覆蓋","weight":0.3,"level":"must","score":5,"evidence":"六大職責全部映射到工作流步驟"},{"name":"工具完備","weight":0.2,"level":"plus","score":3,"evidence":"有評分腳本，缺報告模板工具"},{"name":"輸出格式規範","weight":0.2,"level":"ref","score":2,"evidence":"僅口頭描述，未定義模板"}]}' | python scripts/match_score.py
```

輸入格式：

```json
{
  "dimensions": [
    {
      "name": "人格定位清晰",
      "weight": 0.3,
      "level": "must | plus | ref",
      "score": 4,
      "evidence": "崗位角色定義明確：負責用戶行為分析並輸出可執行結論"
    }
  ]
}
```

輸出：覆蓋度總分、分級、各維度明細、強覆蓋項（≥4 分）、缺口項（<3 分）、一票否決標記。

## 六、使用紀律

- 評分只基於崗位研究證據，不腦補；證據欄位必填
- 同一個 agent 的所有設計維度用同一套權重，保證可比
- 崗位研究更新時，先改證據再改評分，不搞「看分下菜碟」
- 輸出覆蓋度時必須同時給出置信度說明（證據充分/部分待驗證）
- 覆蓋度低不代表崗位研究失敗，可能是檢索輪次不夠——先補研究再補設計
