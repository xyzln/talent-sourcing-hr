# 能力建模與精準匹配模型

> 配合 `recruit-web-sourcing` 技能第 4 步使用。目標：把「合不合適」從主觀判斷變成可複現的評分。

## 一、能力維度拆解法

從 JD 和業務要求中提取 5-8 個能力維度，按三類歸口：

| 類別 | 含義 | 範例 |
|------|------|------|
| 專業硬技能 | 幹活的硬功夫 | 分散式架構設計、SQL 最佳化、投放策略制定 |
| 業務軟技能 | 成事的軟實力 | 跨部門推進、客戶談判、團隊帶教 |
| 文化適配 | 與組織匹配的底色 | 創業節奏適應、資料驅動決策、開放協作 |

**拆解規則**：
- 每個維度必須可觀察、可提問、可驗證，拒絕「有潛力」「感覺不錯」這類虛詞
- 同一維度不重複歸兩類；JD 裡沒提但業務方口頭強調的，補錄並標記來源
- 維度數量控制在 5-8 個：少於 5 個容易漏評，多於 8 個權重稀釋

## 二、0-5 級行為錨定量表

每個維度按五級定義「長什麼樣」，評分時對號入座：

| 分數 | 等級 | 行為錨定（通用表述） |
|------|------|---------------------|
| 5 | 精通 | 有可驗證的標杆產出（主導過同規模/同難度專案，成果被產業或公司認可） |
| 4 | 熟練 | 獨立完整交付過同類工作，品質穩定，幾乎不需要指導 |
| 3 | 勝任 | 在指導下完成過同類工作，能處理常規場景 |
| 2 | 入門 | 接觸過但未獨立交付，或僅有培訓/課程級經驗 |
| 1 | 了解 | 僅概念認知，無實踐 |
| 0 | 無證據 | 公開資訊中找不到任何證據（不表示不會，表示無法驗證） |

**錨定範例（以「高併發系統設計」為例）**：
- 5：主導過日均千萬級請求系統的架構設計，有公開分享或可查案例
- 4：獨立負責過百萬級請求系統的核心模組
- 3：參與過高併發系統開發，負責其中若干模組
- 2：學習/練習專案涉及，未上生產
- 1：僅課程或概念了解
- 0：無任何相關資訊

**證據規則**：無證據 = 0 分並標記「待驗證」；面試/背調後獲得的證據可更新評分，更新時保留評分歷史。

## 三、權重設置

| 權重級 | 含義 | 建議權重 | 計分規則 |
|--------|------|---------|---------|
| 必備項（一票否決） | 不滿足則整體不匹配 | 0.25-0.35 | 得分 ≤2 → 標記 VETO，總分仍計算但結論必須提示 |
| 加分項 | 顯著超出則優先 | 0.10-0.20 | 正常計入 |
| 參考項 | 影響邊緣判斷 | 0.05-0.10 | 正常計入 |

權重之和必須為 1.0；必備項一般設 1-2 個，超過 2 個說明畫像沒收斂。

## 四、匹配度計算與分級

用 `scripts/match_score.py` 計算：加權平均（0-5 分制）× 20 = 匹配度百分制。

| 匹配度 | 分級 | 行動建議 |
|--------|------|---------|
| ≥85 | A 優先尋訪 | 立即觸達，準備定向話術 |
| 70-84 | B 可培養 | 觸達同時評估缺口項的培養成本與週期 |
| 50-69 | C 謹慎 | 僅當供給緊張時作為替代人選，明確缺口 |
| <50 | D 不匹配 | 不進入尋訪清單 |
| 任意必備項 ≤2 | 一票否決 | 無論總分，預設 D，除非業務方明確豁免 |

## 五、match_score.py 用法

```bash
# 輸入 JSON（檔案或標準輸入），輸出匹配度報告
python scripts/match_score.py scores.json
echo '{"dimensions":[{"name":"高併發系統設計","weight":0.3,"level":"must","score":4,"evidence":"主導過日均千萬級請求系統"},{"name":"團隊帶教","weight":0.2,"level":"plus","score":3,"evidence":"帶過5人小組"}]}' | python scripts/match_score.py
```

輸入格式：

```json
{
  "dimensions": [
    {
      "name": "高併發系統設計",
      "weight": 0.3,
      "level": "must | plus | ref",
      "score": 4,
      "evidence": "主導過日均千萬級請求系統架構"
    }
  ]
}
```

輸出：匹配度總分、分級、各維度明細、優勢項（≥4 分）、缺口項（<3 分）、一票否決標記。

## 六、使用紀律

- 評分只基於公開管道證據，不腦補；證據欄位必填
- 同一職位的所有候選線索用同一套維度和權重，保證可比
- 業務要求變化時，先改畫像和權重，再重評，不搞「看人下菜碟」
- 輸出匹配度時必須同時給出置信度說明（證據充分/部分待驗證）
