> 配合 `recruit-web-sourcing` 技能第 5 步使用。所有智能體設計結論按此結構輸出，結論先行。

# 「{Agent 名稱}」智能體設計規格

- **需求方**：{使用者/團隊}
- **用途**：{這個 agent 干什么}
- **落地形態**：{專家包 / 獨立技能 / 子 agent}
- **資料取得時間**：{YYYY-MM-DD}
- **設計師**：智能體設計師

## 一、結論先行（TL;DR）

用 3-5 句話回答使用者最關心的三個問題：

1. **這個 agent 是什么**：一句話定位 + 對應的現實崗位是什么
2. **設計依據**：崗位研究覆蓋了哪些要素、信源品質如何
3. **覆蓋度與落地**：覆蓋度總分與分級 + 建議的落地形態與下一步

## 三、Agent 設計規格

### 3.1 Frontmatter

```yaml
---
name: {agent-name}
description: {什么時候激活這個 agent——用途 + 觸發條件}
displayName:
  zh: {中文顯示名}
  en: {English display name}
profession:
  zh: {專業領域}
  en: {profession}
---
```

### 3.2 人格定位

{2-4 句話：這個 agent 是誰、專治什么問題、方法论是什么、和通用 agent 的區別}

### 3.3 核心能力

{3-5 條，每條對應崗位研究中的職責/任職要求，註明證據來源}

### 3.4 工作流

{分步驟，每步有明確動作、輸入、產出與檢查點；對應崗位真實工作流}

### 3.5 工具與腳本

{需要的工具、腳本清單；沒有則寫「無，純對話流程」}

### 3.6 邊界鐵律

{不做什么、合規紅線、什么情況下拒絕執行}

### 3.7 驗收標準

{怎么算這個 agent 干得好——對應崗位考核指標}

## 六、風險與備選

| 風險 | 影響 | 應對 |
|------|------|------|
| 崗位研究證據不足 | 設計覆蓋度低 | 擴大檢索渠道，優先 L1/L2 一手資料 |
| 崗位要素跨多個崗位 | 設計發散 | 收斂到核心職責，拆成多個 agent |
| 落地形態選錯 | 啟用方式不對 | 按使用頻率與復用性重新評估形態 |
