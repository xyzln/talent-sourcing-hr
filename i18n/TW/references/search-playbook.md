# 現實崗位設計研究文件（Search Playbook）

> 配合 `recruit-web-sourcing` 技能第 2 步使用。目標：用有限的檢索輪次，系統性搞清現實中某個崗位是怎么設計的——職責、任職要求、工作流、協作介面、考核指標、工具棧。

## 一、管道分層矩陣

| 層級 | 管道類型 | 典型管道 | 主要用途 | 信源品質 |
|------|---------|---------|---------|---------|
| L1 | 招聘網站 | Boss直聘、智聯招聘、獵聘、拉勾、前程無憂；海外：LinkedIn、Indeed、Glassdoor | 崗位職責、任職要求、薪資帶寬、在招密度 | 高（一手 JD） |
| L2 | 組織設計資料 | 崗位說明書、職級體系、R&R（職責表）、組織架構圖、公司公開手冊/Wiki | 崗位定位、匯報關係、職責邊界 | 高（一手資料，但公開的少） |
| L3 | 從業者社群 | 脈脈、知乎、V2EX、GitHub、Stack Overflow、掘金、公眾號、技術部落格 | 真實工作流、協作方式、日常痛點、工具棧 | 中高（本人發布，需甄別個案） |
| L4 | 產業報告與方法论 | 咨詢公司崗位模型、HR 方法论、敏捷/DevOps/ITIL 等實踐框架、薪酬調研報告 | 崗位設計範式、考核指標、市場行情 | 中（注意發布時間與適用邊界） |

**執行順序**：先 L1 摸崗位職責與任職要求 → 再 L2/L3 補工作流、協作與工具棧 → 最後用 L4 校準設計範式與考核指標。

## 二、關鍵字矩陣建構法

按四個詞族交叉組合，每輪檢索取 2-4 個組合：

| 詞族 | 說明 | 範例（資料分析師） |
|------|------|-------------------|
| 崗位詞 | 職位名稱的同義與變體 | 資料分析師、資料營運、BI 工程師、Data Analyst |
| 職責詞 | 崗位干什么 | 用戶行為分析、報表體系、AB 實驗、指標體系搭建 |
| 場景詞 | 業務場景與產業 | 電商、SaaS、金融科技、廣告投放 |
| 設計詞 | 崗位設計相關資料 | 崗位說明書、職責、任職要求、績效考核、OKR、職級 |

**組合範例**：
- 「資料分析師 崗位職責 任職要求 招聘」→ 摸 L1 職責與要求
- 「資料分析師 一天的工作 工作流」→ 挖 L3 真實日常
- 「資料分析師 績效考核 指標 OKR」→ 查考核指標
- 「site:zhihu.com 資料分析師 工作日常」→ 定向挖從業者分享

## 三、檢索指令速查

| 指令 | 作用 | 範例 |
|------|------|------|
| `site:` | 限定網站 | `site:linkedin.com data analyst` |
| `intitle:` | 標題必含 | `intitle:崗位說明書 產品經理` |
| `filetype:` | 限定檔案類型 | `filetype:pdf 崗位說明書 財務` |
| `""` | 精確匹配 | `"用戶成長負責人"` |
| `-` | 排除噪音 | `資料分析 -培訓 -保安` |
| 時間過濾 | 控制時效 | JD/方法论類檢索優先選近 3 年 |

## 四、崗位設計六要素采集清單

每研究一個崗位，按這張表過一遍，缺項繼續補檢：

| 要素 | 采集內容 | 主管道 |
|------|---------|--------|
| 職責 | 具體干什么，拆到可執行動作項 | L1 JD、L2 崗位說明書 |
| 任職要求 | 知識、技能、經驗、資質證書 | L1 JD |
| 工作流 | 工作步驟、順序、週期、檢查點 | L3 從業者分享、L4 方法论 |
| 協作介面 | 上游給什么、下游接什么、向誰匯報 | L2 組織架構、L3 |
| 考核指標 | 怎么算干得好（品質/效率/結果） | L4 方法论、L1 JD 加分描述 |
| 工具棧 | 用什么工具、系統、模板干活 | L3、L1 JD |

## 五、常見崗位研究路徑（速查）

| 崗位類型 | 優先管道 | 研究技巧 |
|---------|---------|---------|
| 研發（前後端/演算法） | L1 + GitHub/掘金/技術部落格 | 看 JD 技能要求 + 工程師寫的真實工作流與協作吐槽 |
| 產品 | L1 + 脈脈/知乎/公眾號 | 搜產品經理寫的 PRD 流程、需求評審經驗 |
| 設計 | L1 + Behance/Dribbble/站酷 | 看作品集說明 + 設計師寫的協作流程 |
| 營運/市場 | L1 + 公眾號/知乎 | 搜操盤過的知名案例復盤（署名+流程） |
| 銷售/商務 | L1 + 脈脈/產業媒體 | 按目標客戶群反查「做過同類客戶」的崗位設計 |
| 職能（HR/財務/法務） | L1 + 垂直社群 + L4 | 按產業資質證書反查（CPA、法律職業資格等） |
| 管理崗 | L2 + L4 + L3 | 重點查匯報關係、協作介面與考核指標 |

## 六、檢索紀律

- 每輪檢索只驗證一個假設，避免一鍋燉
- 同一結論至少兩個獨立信源交叉驗證；職責與任職要求以 L1 在招 JD 為主、報告為輔
- 所有研究結論必須標註「資料取得時間：YYYY-MM-DD」
- 連續兩輪無有效命中 → 換詞族或換管道，不重複同一檢索式超過兩次
- 從業者社群內容注意甄別個案與共識：多人獨立描述一致才可作為崗位設計證據
