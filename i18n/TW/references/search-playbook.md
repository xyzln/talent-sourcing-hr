# 全網檢索策略文件（Search Playbook）

> 配合 `recruit-web-sourcing` 技能第 2、3 步使用。目標：用有限的檢索輪次，系統性覆蓋人才供給資訊。

## 一、管道分層矩陣

| 層級 | 管道類型 | 典型管道 | 主要用途 | 信源品質 |
|------|---------|---------|---------|---------|
| L1 | 招聘網站 | Boss直聘、智聯招聘、獵聘、拉勾、前程無憂；海外：LinkedIn、Indeed、Glassdoor | 在招職位、薪資帶寬、任職要求、人才密度 | 高（一手 JD） |
| L2 | 社群與專業社群 | 脈脈、知乎、GitHub、Stack Overflow、V2EX、掘金、Behance/Dribbble（設計） | 候選線索、真實作品、技術影響力 | 中高（本人發布） |
| L3 | 競品與產業動態 | 競品公司官網招聘頁、融資/產品新聞、產業媒體 | 競品擴編方向、人才流動訊號 | 中（需交叉驗證） |
| L4 | 產業報告與資料 | 薪酬調研報告、人才市場報告、招聘平台白皮書 | 薪資行情、供需趨勢 | 中（注意發布時間） |

**執行順序**：先 L1 摸供給密度與薪資帶寬 → 再 L2/L3 挖具體線索 → 最後用 L4 校準行情結論。

## 二、關鍵字矩陣建構法

按四個詞族交叉組合，每輪檢索取 2-4 個組合：

| 詞族 | 說明 | 範例（高階後端工程師） |
|------|------|----------------------|
| 職位詞 | 職位名稱的同義與變體 | 後端工程師、服務端工程師、Java 開發、Backend Engineer |
| 技能詞 | 硬技能與工具鏈 | 分散式、微服務、高併發、Kubernetes、Go、Spring Cloud |
| 場景詞 | 業務場景與產業 | 電商中台、支付系統、SaaS、金融科技、廣告系統 |
| 管道詞 | 網站與站內定向 | site:zhipin.com、site:linkedin.com、site:github.com |

**組合範例**：
- 「高階後端工程師 微服務 高併發 招聘」→ 摸 L1 供給
- 「site:github.com 高併發 Java 開源」→ 挖 L2 技術型線索
- 「支付系統 架構師 招聘 薪資」→ 查薪資帶寬

## 三、檢索指令速查

| 指令 | 作用 | 範例 |
|------|------|------|
| `site:` | 限定網站 | `site:liepin.com 演算法工程師` |
| `intitle:` | 標題必含 | `intitle:招聘 資料分析師` |
| `filetype:` | 限定檔案類型 | `filetype:pdf 薪酬報告 2025` |
| `""` | 精確匹配 | `"用戶成長負責人"` |
| `-` | 排除噪音 | `招聘 -培訓 -保安` |
| 時間過濾 | 控制時效 | 新聞/職位類檢索優先選近 3-12 個月 |

## 四、供給密度評估（第 3 步怎麼判斷「好不好找」）

對每輪檢索結果統計四項指標，填入尋訪報告：

1. **在招職位量**：L1 管道在招職位數量級（如「Boss 直聘在招約 500+」）
2. **薪資帶寬**：市場主流區間與分位（P25/P50/P75），標記資料取得時間
3. **人才聚集地**：哪些公司/城市/社群該人群密集（競品清單）
4. **稀缺訊號**：職位長期掛招、薪資上浮、要求放寬（供不應求）或相反

**結論分檔**：
- 供給充足（在招職位量大、薪資平穩）→ 建議標準適度上調，篩選重點放在能力匹配
- 供給緊張（職位少、薪資上浮、要求放寬）→ 建議提前布局、放寬替代人群、提高薪酬預算
- 結構性稀缺（總量大但符合硬性條件的少）→ 收緊閉卡條件優先級，找「最近鄰」人群

## 五、常見職位尋訪路徑（速查）

| 職位類型 | 優先管道 | 線索挖掘技巧 |
|---------|---------|-------------|
| 研發（前後端/演算法） | L1 + GitHub/Juejin | 搜開源專案貢獻者、技術部落格作者 |
| 產品 | L1 + 脈脈/知乎 | 搜產品分析文章作者、競品產品動態 |
| 設計 | L1 + Behance/Dribbble | 直接看作品集，按專案類型反查作者 |
| 營運/市場 | L1 + 公眾號/知乎 | 搜操盤過的知名案例署名 |
| 銷售/商務 | L1 + 脈脈 | 按目標客戶群反查「做過同類客戶」的人 |
| 職能（HR/財務/法務） | L1 + 垂直社群 | 按產業資質證書反查（CPA、法律職業資格等） |

## 六、檢索紀律

- 每輪檢索只驗證一個假設，避免一鍋燉
- 同一結論至少兩個獨立信源交叉驗證；招聘薪資以 L1 在招 JD 為主、報告為輔
- 所有行情資料必須標記「資料取得時間：YYYY-MM-DD」
- 連續兩輪無有效命中 → 換詞族或換管道，不重複同一檢索式超過兩次
