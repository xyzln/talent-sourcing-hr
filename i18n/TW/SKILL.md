# 全網招聘尋訪與能力匹配工作流

## 用途

把業務方的職位/用工要求轉化為可執行的人才尋訪行動：結構化需求 → 設計並執行全網檢索 → 建立能力模型並精準匹配 → 輸出尋訪報告與行動建議。

## 使用時機

- 使用者给出 JD 或業務要求，要求「找人 / 檢索人才 / 看人才市場 / 對標競品招聘」
- 使用者要求按能力維度篩選、匹配、排序候選線索
- 使用者要求輸出人才尋訪報告、人才地圖或招聘市場洞察簡報

## 五步流程

### 第 1 步：需求澄清與結構化

把業務要求轉成結構化人才畫像；缺資訊先提問，不假設。輸出四張表：

- **硬性條件**：職級 / 年資 / 學歷 / 產業背景 / 地點 / 薪資帶寬 / 到職時間
- **能力維度**：專業硬技能、業務軟技能、文化適配項
- **權重標註**：必備項（一票否決）/ 加分項 / 參考項
- **檢索對象**：目標公司、目標人群、替代人群

### 第 2 步：檢索策略設計

基於人才畫像生成檢索關鍵字矩陣（職位詞 × 技能詞 × 場景詞 × 管道詞）與目標管道清單。方法與範例見 `references/search-playbook.md`：

- 管道分層：招聘網站 / 社群與專業社群 / 競品動態 / 產業報告
- 每輪檢索設定明確目標：驗證供給密度 / 挖具體線索 / 查薪資與市場行情
- 關鍵字變體：同義詞、縮寫、中英混排（如「後端」「服務端」「Backend」）

### 第 3 步：全網檢索執行

逐輪執行檢索，遵守以下紀律：

- 每輪記錄：檢索式、管道、命中數量、信源品質、取得時間
- 交叉驗證：同一結論至少兩個獨立信源；優先官方/一手來源
- 行情與招聘動態類資料必須標記取得日期
- 單輪無有效命中時，回到第 2 步放寬關鍵字或更換管道，不死磕同一檢索式

### 第 4 步：能力建模與精準匹配

1. 把職位要求拆成 5-8 個可評分能力維度，建立 0-5 級行為錨定（評什麼、幾分長什麼樣）
2. 對每條候選線索按維度打分，只基於履歷/主頁/專案描述中的證據打分，無證據不評分
3. 執行 `scripts/match_score.py` 計算加權匹配度（輸入評分 JSON，輸出總分、優勢項、缺口項、一票否決標記）
4. 評分模型、錨定範例與匹配度分級見 `references/capability-matching-model.md`

### 第 5 步：尋訪報告輸出

按 `references/report-template.md` 輸出報告：結論先行、人才供給概況、Top 線索表（含匹配度與證據）、觸達建議、風險與備選。結尾給業務方 3 個可立即執行的下一步動作。

## 鐵律

- 只依據職位相關能力與證據評價，嚴禁年齡、性別、地域、婚育、戶籍等歧視性維度
- 不編造信源與候選人；檢索不到就如實說明，並給出擴搜建議
- 只使用公開管道資訊，保護個人隱私
- 所有結論標記信源與取得時間
