# 岗位 → 智能体设计映射模型

> 配合 `recruit-web-sourcing` 技能第 3、4 步使用。目标：把「岗位设计」翻译成「agent 设计」，并用可复现的覆盖度评分验证设计完整性。

## 一、岗位设计要素 → Agent 设计要素映射表

| 岗位设计要素 | Agent 设计要素 | 落地位置 |
|-------------|---------------|---------|
| 角色定位（这岗位是干什么的） | 智能体定位 | frontmatter description + 人格开场段 |
| 职责（具体干什么） | 技能清单与工作流步骤 | skills 数组 + 工作流章节 |
| 任职要求（靠什么胜任） | 能力锚定与边界铁律 | 人格核心能力 + 铁律/注意事项 |
| 工作流（怎么干、什么顺序） | 工作流步骤与检查点 | 工作流章节（每步有动作和产出） |
| 协作界面（跟谁打交道） | 输入输出规格与交接协议 | 输出规范 + 触发/退出条件 |
| 考核指标（怎么算干得好） | 验收标准与质量门槛 | 输出规范中的合格线 |
| 工具栈（用什么干） | 工具与脚本清单 | scripts/ + 参考手册 + 工具说明 |

**映射规则**：
- 岗位上有的要素，agent 必须有对应设计；岗位上没有的，agent 也不许凭空发明
- 每项映射必须能回溯到岗位研究证据（信源 + 获取时间）
- 一个岗位要素可以映射到多个 agent 要素，但一个 agent 要素必须至少有一个岗位来源

## 二、Agent 设计覆盖度锚定（0-5 级）

对每个 agent 设计维度打分，对照岗位研究证据「对号入座」：

| 分数 | 等级 | 行为锚定（通用表述） |
|------|------|---------------------|
| 5 | 完整覆盖 | 岗位要素全部翻译，且每项都有证据支撑，可直接落地 |
| 4 | 覆盖无遗漏 | 主要要素全部覆盖，细节处可再打磨 |
| 3 | 基本覆盖 | 主体覆盖，但有明确小缺口（缺验收标准/缺触发条件等） |
| 2 | 部分覆盖 | 只覆盖了一半左右要素，多处凭感觉补 |
| 1 | 名义覆盖 | 提到了该维度，但没有可执行内容 |
| 0 | 无证据 | 岗位研究中找不到支撑该设计的任何证据（不表示不该做，表示无法验证） |

**证据规则**：无证据 = 0 分并标注「待验证」；补充检索获得证据后可更新评分，更新时保留评分历史。

## 三、常见设计维度与权重

从岗位设计研究中提取 5-8 个设计维度，按三类归口：

| 权重级 | 含义 | 建议权重 | 计分规则 |
|--------|------|---------|---------|
| 核心项（一票否决） | 缺了 agent 就不成立 | 0.25-0.35 | 得分 ≤2 → 标记 VETO，总分仍计算但结论必须提示 |
| 加分项 | 显著提升 agent 质量 | 0.10-0.20 | 正常计入 |
| 参考项 | 影响边缘判断 | 0.05-0.10 | 正常计入 |

**典型维度**（按岗位裁剪，不必全用）：
- 核心：人格定位清晰、职责覆盖、工作流完整
- 加分：协作界面明确、验收标准可执行、工具齐备
- 参考：输出格式规范、时效标注机制

权重之和必须为 1.0；核心项一般设 1-2 个，超过 2 个说明设计没收敛。

## 四、设计覆盖度计算与分级

用 `scripts/match_score.py` 计算：加权平均（0-5 分制）× 20 = 覆盖度百分制。

| 覆盖度 | 分级 | 行动建议 |
|--------|------|---------|
| ≥85 | A 可直接落地 | 按规格直接建成专家包 / 技能 / 子 agent |
| 70-84 | B 基本可用 | 落地同时补齐缺口项（补研究或补设计） |
| 50-69 | C 有缺口 | 先补岗位研究或补设计，再落地 |
| <50 | D 不匹配 | 回到第 2 步重新研究岗位，不急着生成 |
| 任意核心项 ≤2 | 一票否决 | 无论总分，默认 D，除非需求方明确豁免 |

## 五、match_score.py 用法

```bash
# 输入 JSON（文件或标准输入），输出覆盖度报告
python scripts/match_score.py scores.json
echo '{"dimensions":[{"name":"人格定位清晰","weight":0.3,"level":"must","score":4,"evidence":"岗位角色定义明确：负责用户行为分析并输出可执行结论"},{"name":"职责覆盖","weight":0.3,"level":"must","score":5,"evidence":"六大职责全部映射到工作流步骤"},{"name":"工具齐备","weight":0.2,"level":"plus","score":3,"evidence":"有评分脚本，缺报告模板工具"},{"name":"输出格式规范","weight":0.2,"level":"ref","score":2,"evidence":"仅口头描述，未定义模板"}]}' | python scripts/match_score.py
```

输入格式：

```json
{
  "dimensions": [
    {
      "name": "人格定位清晰",
      "weight": 0.3,
      "level": "must | plus | ref",
      "score": 4,
      "evidence": "岗位角色定义明确：负责用户行为分析并输出可执行结论"
    }
  ]
}
```

输出：覆盖度总分、分级、各维度明细、强覆盖项（≥4 分）、缺口项（<3 分）、一票否决标记。

## 六、使用纪律

- 评分只基于岗位研究证据，不脑补；证据字段必填
- 同一个 agent 的所有设计维度用同一套权重，保证可比
- 岗位研究更新时，先改证据再改评分，不搞「看分下菜碟」
- 输出覆盖度时必须同时给出置信度说明（证据充分/部分待验证）
- 覆盖度低不代表岗位研究失败，可能是检索轮次不够——先补研究再补设计
