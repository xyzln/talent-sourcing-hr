> 配合 `recruit-web-sourcing` 技能第 5 步使用。所有智能体设计结论按此结构输出，结论先行。

# 「{Agent 名称}」智能体设计规格

- **需求方**：{用户/团队}
- **用途**：{这个 agent 干什么}
- **落地形态**：{专家包 / 独立技能 / 子 agent}
- **数据获取时间**：{YYYY-MM-DD}
- **设计师**：智能体设计师

## 一、结论先行（TL;DR）

用 3-5 句话回答用户最关心的三个问题：

1. **这个 agent 是什么**：一句话定位 + 对应的现实岗位是什么
2. **设计依据**：岗位研究覆盖了哪些要素、信源质量如何
3. **覆盖度与落地**：覆盖度总分与分级 + 建议的落地形态与下一步

## 三、Agent 设计规格

### 3.1 Frontmatter

```yaml
---
name: {agent-name}
description: {什么时候激活这个 agent——用途 + 触发条件}
displayName:
  zh: {中文显示名}
  en: {English display name}
profession:
  zh: {专业领域}
  en: {profession}
---
```

### 3.2 人格定位

{2-4 句话：这个 agent 是谁、专治什么问题、方法论是什么、和通用 agent 的区别}

### 3.3 核心能力

{3-5 条，每条对应岗位研究中的职责/任职要求，注明证据来源}

### 3.4 工作流

{分步骤，每步有明确动作、输入、产出与检查点；对应岗位真实工作流}

### 3.5 工具与脚本

{需要的工具、脚本清单；没有则写「无，纯对话流程」}

### 3.6 边界铁律

{不做什么、合规红线、什么情况下拒绝执行}

### 3.7 验收标准

{怎么算这个 agent 干得好——对应岗位考核指标}

## 五、落地方式

- **推荐形态**：{专家包 / 独立技能 / 子 agent} + 一句话理由
- **启用步骤**：{复制到哪个目录、如何激活、如何验证}

## 六、风险与备选

| 风险 | 影响 | 应对 |
|------|------|------|
| 岗位研究证据不足 | 设计覆盖度低 | 扩大检索渠道，优先 L1/L2 一手资料 |
| 岗位要素跨多个岗位 | 设计发散 | 收敛到核心职责，拆成多个 agent |
| 落地形态选错 | 启用方式不对 | 按使用频率与复用性重新评估形态 |
