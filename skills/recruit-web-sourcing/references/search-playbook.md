# 全网检索策略手册（Search Playbook）

> 配合 `recruit-web-sourcing` 技能第 2、3 步使用。目标：用有限的检索轮次，系统性覆盖人才供给信息。

## 一、渠道分层矩阵

| 层级 | 渠道类型 | 典型渠道 | 主要用途 | 信源质量 |
|------|---------|---------|---------|---------|
| L1 | 招聘站点 | Boss直聘、智联招聘、猎聘、拉勾、前程无忧；海外：LinkedIn、Indeed、Glassdoor | 在招岗位、薪资带宽、任职要求、人才密度 | 高（一手 JD） |
| L2 | 社交与专业社区 | 脉脉、知乎、GitHub、Stack Overflow、V2EX、掘金、Behance/Dribbble（设计） | 候选线索、真实作品、技术影响力 | 中高（本人发布） |
| L3 | 竞对与行业动态 | 竞对公司官网招聘页、融资/产品新闻、行业媒体 | 竞对扩编方向、人才流动信号 | 中（需交叉验证） |
| L4 | 行业报告与数据 | 薪酬调研报告、人才市场报告、招聘平台白皮书 | 薪资行情、供需趋势 | 中（注意发布时间） |

**执行顺序**：先 L1 摸供给密度与薪资带宽 → 再 L2/L3 挖具体线索 → 最后用 L4 校准行情结论。

## 二、关键词矩阵构建法

按四个词族交叉组合，每轮检索取 2-4 个组合：

| 词族 | 说明 | 示例（高级后端工程师） |
|------|------|----------------------|
| 岗位词 | 职位名称的同义与变体 | 后端工程师、服务端工程师、Java 开发、Backend Engineer |
| 技能词 | 硬技能与工具链 | 分布式、微服务、高并发、Kubernetes、Go、Spring Cloud |
| 场景词 | 业务场景与行业 | 电商中台、支付系统、SaaS、金融科技、广告系统 |
| 渠道词 | 站点与站内定向 | site:zhipin.com、site:linkedin.com、site:github.com |

**组合示例**：
- 「高级后端工程师 微服务 高并发 招聘」→ 摸 L1 供给
- 「site:github.com 高并发 Java 开源」→ 挖 L2 技术型线索
- 「支付系统 架构师 招聘 薪资」→ 查薪资带宽

## 三、检索指令速查

| 指令 | 作用 | 示例 |
|------|------|------|
| `site:` | 限定站点 | `site:liepin.com 算法工程师` |
| `intitle:` | 标题必含 | `intitle:招聘 数据分析师` |
| `filetype:` | 限定文件类型 | `filetype:pdf 薪酬报告 2025` |
| `""` | 精确匹配 | `"用户增长负责人"` |
| `-` | 排除噪音 | `招聘 -培训 -保安` |
| 时间过滤 | 控制时效 | 新闻/职位类检索优先选近 3-12 个月 |

## 四、供给密度评估（第 3 步怎么判断「好不好找」）

对每轮检索结果统计四项指标，填入寻访报告：

1. **在招岗位量**：L1 渠道在招岗位数量级（如「Boss 直聘在招约 500+」）
2. **薪资带宽**：市场主流区间与分位（P25/P50/P75），标注数据获取时间
3. **人才聚集地**：哪些公司/城市/社区该人群密集（竞对清单）
4. **稀缺信号**：职位长期挂招、薪资上浮、要求放宽（供不应求）或相反

**结论分档**：
- 供给充足（在招岗位量大、薪资平稳）→ 建议标准适度上调，筛选重点放在能力匹配
- 供给紧张（岗位少、薪资上浮、要求放宽）→ 建议提前布局、放宽替代人群、提高薪酬预算
- 结构性稀缺（总量大但符合硬性条件的少）→ 收紧闭卡条件优先级，找「最近邻」人群

## 五、常见岗位寻访路径（速查）

| 岗位类型 | 优先渠道 | 线索挖掘技巧 |
|---------|---------|-------------|
| 研发（前后端/算法） | L1 + GitHub/掘金 | 搜开源项目贡献者、技术博客作者 |
| 产品 | L1 + 脉脉/知乎 | 搜产品分析文章作者、竞对产品动态 |
| 设计 | L1 + Behance/Dribbble | 直接看作品集，按项目类型反查作者 |
| 运营/市场 | L1 + 公众号/知乎 | 搜操盘过的知名案例署名 |
| 销售/商务 | L1 + 脉脉 | 按目标客户群反查「做过同类客户」的人 |
| 职能（HR/财务/法务） | L1 + 垂直社区 | 按行业资质证书反查（CPA、法律职业资格等） |

## 六、检索纪律

- 每轮检索只验证一个假设，避免一锅炖
- 同一结论至少两个独立信源交叉验证；招聘薪资以 L1 在招 JD 为主、报告为辅
- 所有行情数据必须标注「数据获取时间：YYYY-MM-DD」
- 连续两轮无有效命中 → 换词族或换渠道，不重复同一检索式超过两次
